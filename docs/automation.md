# 後續自動化計畫

這份計畫完成 README 的「Plan further auto features」。目前版本已提供目標、久坐／久站提醒與一次性倒數；尚未啟用自動升降。

## 優先順序

| 階段 | 功能 | 觸發與操作 | 驗收與前置條件 |
| --- | --- | --- | --- |
| A1 | 坐站週期提醒 | 使用者啟動一個工作 session，輪流提醒坐／站；可暫停、跳過、結束 | 注入時鐘測跨姿勢、暫停、背景恢復；提醒本身不送馬達指令 |
| A2 | 星期與工作時段 | 設定工作日、起訖及午休；時段外不提醒 | 測午夜、週末、時區、夏令時間、設定修改；明確顯示下次觸發時間 |
| A3 | 手動確認的姿勢切換 | 通知中顯示建議姿勢與已儲存高度，使用者確認後才移動 | 需完成 BLE transport 與實機停止驗收；通知取消不移動；確認時重新檢查連線和能力 |
| A4 | Android 捷徑與小工具 | 使用者點選坐姿／站姿／停止；命令走同一控制核心 | App 不在前景也要明確執行狀態和可停止入口；不從過期 PendingIntent 重播移動 |
| A5 | 使用者主動啟動的自動坐站 session | 在指定時間內依週期移動；每次預告並允許取消 | 先完成 A1–A4、原 App 相容與實機故障矩陣；手動操作／停止／故障立即暫停自動 session |
| A6 | 外部整合 | 視需求加入 Home Assistant、本機 API 或桌面捷徑 | 先確認主要使用情境；再定義身份、連線所有權與重放防護。沒有已確認需求前不建伺服器 |

## 自動移動的狀態模型

`停止 → 使用者啟動 → 等待 → 預告 → 再次檢查條件 → 移動 → 等待`。

任一階段遇到使用者停止、硬體鎖、故障、連線中斷或時段結束，進入「暫停／需要使用者介入」。重新連線和程序重啟只恢復設定，不恢復正在執行的移動。

同一時間僅一個移動命令擁有者。優先權為：停止／故障 > 使用者手動操作 > 自動 session。使用者手動操作使自動 session 暫停；不得在手動放開後立刻把桌子拉回原排程高度。

Android 背景執行與 inexact alarm 不能被假設為準時控制器。先決定要的是通知、App 前景 session，或有常駐連線的獨立控制器，再選 Foreground Service／Companion Device 等做法。

## 每項自動化的固定驗收

- 注入時鐘和模擬桌後，測正常觸發、手動覆寫、取消、錯過時段、時區改變、程序重啟及重複觸發。
- 顯示下一個動作與時間；使用者可從同一畫面停止／暫停。
- 調整設定立即使舊排程失效；重複通知不產生重複馬達指令。
- 移動前重新取得新鮮高度／鎖定／故障狀態，狀態不足時不移動。
- Android 模擬器通過只能放行軟體邏輯；硬體自動升降另外通過實機矩陣。

## 暫不決定的產品事項

使用者希望的坐站節奏、工作時段、Android 以外平台，以及是否需要無手機常駐的外部控制器，仍可依實際使用再定。這些不阻擋 A1 的純軟體狀態模型。
